## Completion status

All game code is decompiled. `make complete` proves it and fails if any of this stops being true:

- The built ROM is byte-identical to the original, compressed and decompressed.
- No C file imports assembly (no `GLOBAL_ASM`).
- Every byte of `.text` comes from C, handwritten assembly tracked in `src/`, libultra, Nintendo's RSP microcode, or the overlay syscall table built from `overlays.us.toml`.

Not everything is C, and the tool prints the split per section:

- **Handwritten assembly:** the 104 functions in `src/**/*.s` were written by hand in the original game, so no C source can produce them. They use fixed global registers, private calling conventions, COP0 access or 64-bit instructions.
- **Data:** most non-asset `.data`, some `.rodata` and `.bss` are still plain words generated by splat. They are byte-exact but not yet typed C.
- **Binary blobs:** game assets and RSP microcode stay binary.
- **Readability:** matching C can still contain workarounds, and many names are still addresses.

## Setup

For the native PC source-port work and its current limitations, see
[pc/native/README.md](pc/native/README.md). The steps below build the original N64 ROM.

- Clone this repo recursively with git.
  - If you've already cloned, then init submodules recursively instead.
  - `git submodule update --init --recursive`
- Install packages for the C++ libraries fmtlib and toml11.
  - Ubuntu: `sudo apt install libfmt-dev libtoml11-dev gcc-mips-linux-gnu`
- Install pip requirements for splat.
  - `python3 -m pip install -r tools/splat/requirements.txt`
- Install pip requirements for this project.
  - `python3 -m pip install -r tools/requirements.txt`
- Place a copy of Banjo Tooie NTSC-U (SHA1 = af1a89e12b638b8d82cc4c085c8e01d4cba03fb3) in this folder and name it `baserom.us.z64`.
- Run `make setup` to decompress the rom and split it.
- Run `make` (with an optional job count) to build the rom.
- Run `make complete` to verify the completion status above.

## Autonomous matching harness

The [decompilation harness](tools/decomp_harness/README.md) tries local C patterns before starting isolated Codex CLI
workers with ChatGPT authentication, persists progress in SQLite, and accepts a
match only after a complete ROM comparison. Start with `./decomp-agent doctor`,
`./decomp-agent scan`, and `./decomp-agent run --dry-run`.
